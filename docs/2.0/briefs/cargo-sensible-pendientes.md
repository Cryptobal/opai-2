# Seguimiento de cargos sensibles y bonos ocultos

Encargo del 27-oct-2026, apilado sobre #83. Codex aplica el criterio de #83: rechazar las versiones de instalación, puesto y persona cuando el actor no puede ver sus montos, también en vista previa. Así no se sustituyen bonos ocultos. Los rechazos se registran en una transacción posterior al rollback, sin montos; un fallo de auditoría impide responder como si hubiera quedado registrada.

Criterios: (a) enviar sensibilidad solo al cambiarla y aceptar el mismo valor; (b) exigir permiso al crear cargo sensible; (c) bloquear cargo por ID y tenant; (d) rechazar versiones de capas con montos ocultos; (e) auditar rechazos; (f) usar el texto literal solicitado; (g) pruebas de servidor. Las pruebas de servidor cubren el rechazo y la conservación de bonos en puesto y persona, el fallo de auditoría y el bloqueo de un cargo ajeno en Postgres. La concurrencia de versiones está cubierta por la prueba de base existente; el gate local y los E2E desktop afectados pasaron. La QA manual a 375 y 1024 px queda pendiente.
