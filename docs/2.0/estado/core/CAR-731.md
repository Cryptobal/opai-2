# CAR-731 — push nativo iOS (FCM real)

**Sigue a:** PR #1106 (backend FCM HTTP v1 y Capacitor JS).

## Qué entró en este PR

- `AppDelegate.swift`: reenvío de registro APNs → token **FCM** vía `FirebaseMessaging` (SPM, proyecto Firebase opai-d194a / app «OPAI iOS»).
- `FirebasePushIos.swift`: `FirebaseApp.configure()` solo si existe `GoogleService-Info.plist`; sin plist compila y en runtime no crashea (aviso en log / fallo de registro controlado).
- Fase Xcode «Copy GoogleService-Info.plist» (CAR-733 / #1110): copia al bundle el archivo que CI o desarrollo dejan en `App/GoogleService-Info.plist` (la inyección del secreto es solo en `ios-testflight.sh`, no en xcodebuild).
- `CapApp-SPM/Package.swift`: incluye `@capacitor/push-notifications` (tras `cap sync`).
- Pruebas: `apps/web/lib/push-nativo.test.ts` (suscripción iOS + deep link); `push-nativa-db.test.ts` (token FCM iOS).

## Pendiente para criterio real (dispositivo)

1. Build en **TestFlight** con plist inyectado en CI y `aps-environment=production`.
2. Tras login, registro del dispositivo con `plataforma: ios` y token FCM (no hex APNs).
3. Push de prueba por rol desde backend con `FIREBASE_SERVICE_ACCOUNT` activo.
4. Tocar notificación → pantalla de `data.ruta`.

## Decide Carlos

Nada bloqueante en código; llave APNs en Firebase y secreto `GOOGLE_SERVICE_INFO_PLIST` en CI siguen siendo tarea de Apps nativas / infra.
